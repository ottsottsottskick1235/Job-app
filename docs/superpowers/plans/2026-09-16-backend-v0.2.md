# Job App Backend v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an authenticated, multi-tenant, location-aware backend with advanced matching/filtering and auditable application workflows.

**Architecture:** Keep Next.js + Supabase. Verify Supabase Auth tokens in server routes, centralize authorization, keep matching/search/state-machine logic pure and testable, and use service-role database access only after permission checks.

**Tech Stack:** Next.js App Router, TypeScript, Supabase Auth/Postgres, Zod, Node assertions for pure-domain verification.

**Spec:** `docs/superpowers/specs/2026-09-16-backend-v0.2-design.md`

## Global Constraints
- Preserve existing automatic hard-rule matching behavior.
- Soft scores may rank eligible pairs but never make an ineligible pair eligible.
- Keep UI deliberately plain.
- Do not expose the Supabase service-role key to the client.
- Derive identity from auth, not caller-supplied user IDs.
- Keep existing prototype data shape migratable through additive SQL where possible.
